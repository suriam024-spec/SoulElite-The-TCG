## 2. Rule Book คือแหล่งความจริงของกฎเกม

ต้องมีไฟล์ `docs/RULEBOOK_0.5.md` ใน Repo จริง ถ้าไม่มีให้หยุดและบอก OWNER ทีละขั้นว่าต้องส่งออกเอกสารเป็น Markdown แล้วอัปโหลดอย่างไร ห้ามอ้างว่าอ่านแล้วถ้าไม่มีไฟล์ ต้องใช้เวอร์ชันที่ส่งออกจากเอกสารต้นฉบับ ไม่ใช่ข้อความที่คัดลอกจากแชท

ป้ายสถานะใน Rule Book ตรงกับป้ายใน MASTER_PROMPT ดังนี้

| ใน Rule Book | ใช้ในโค้ดและเอกสารว่า |
| --- | --- |
| [ยืนยัน] | CONFIRMED |
| [ชั่วคราว] | PROVISIONAL (ต้องเป็น config) |
| [แนวคิด] | CONCEPT (ห้ามเขียนเป็นกฎ) |
| [รอกำหนด] | TBD (ห้ามเดา) |

ถ้าโค้ดทำต่างจาก Rule Book ถือเป็นบั๊กหรือข้อขัดแย้ง ไม่ใช่กฎใหม่ ห้ามแก้ Rule Book โดยพลการ และห้ามถือข้อเสนอของ DEV ว่าเป็นคำตัดสินของ OWNER

### จุดที่เอนจินต้องระวัง (อ่านรายละเอียดใน Rule Book ตามเลขข้อ)

- สนามและช่อง: ข้อ 3.1 3.4 3.5 (S ใช้ร่วมกับ Fast, M และ S กลางย้ายไม่ได้, เอายูนิตออกไม่นับเป็นถูกทำลาย)
- เปิดเกมและผู้บุกเบิก: ข้อ 2.3 และหมวด 4 (เลือกจากเด็คก่อนจั่ว)
- โทเคน: ข้อ 5.1-5.5 (+1 ตอน Draw, Heart แทนโทเคนได้ ไม่กลับกัน, Heart ขั้นต่ำเป็นเงื่อนไขแยก, จ่าย Life ไม่ได้ถ้าเหลือต่ำกว่า 1)
- เทิร์นและ Ride: หมวด 6
- การต่อสู้และ Life: หมวด 7 และข้อ 5.6 (ยิง Life ตรงให้ Heart แต่ไม่ใช่การโจมตี)
- Impact: หมวด 8 รวม 8.2.1 (ผลออกทันที การชุบ)
- Fast และหน้าต่างตอบสนอง: หมวด 9
- ผังและข้อมูลที่ต้องเก็บ: หมวด 12

## 3. ขอบเขตเฟสแรก

อยู่ในขอบเขต: ยูนิต เวทปกติ Supply อาวุธ Fast Spell Impact โจมตี/ป้องกัน ผู้บุกเบิก

**ไม่เปิดใช้จนกว่า OWNER อนุมัติ** (DEFERRED/CONCEPT): เคาน์เตอร์ Impact, Final Impact, ป้ายกลุ่มย่อยและกลุ่ม SiN, ข้อความสร้างเด็คบนการ์ด, 2v2 ให้เว้นช่อง `tags` ว่างไว้ในโครงข้อมูลการ์ด

ค่า PROVISIONAL ที่ต้องอยู่ในไฟล์ config เดียว: Life เริ่มต้น (10), มือเริ่มต้น (5), โทเคนเริ่มต้น (ราว 5) ปรับตามผลเทส ห้ามฝังในโค้ดกฎ

ข้อมูลการ์ดที่ใช้ทดสอบต้องติดป้ายว่าเป็นข้อมูลทดสอบ ห้ามแต่งความสามารถการ์ดจริง

## 6. กฎเฉพาะของโปรเจกต์นี้

- ความถูกต้องของกฎ (Rule Correctness) แยกจากความสมดุลและความสนุก ห้ามปรับตัวเลขการ์ดหรือค่าเริ่มต้นเพื่อ "ให้เกมสนุกขึ้น" โดยพลการ ค่า PROVISIONAL ปรับได้เมื่อ OWNER สั่งหลังเทสเท่านั้น
- ไม่ต้องจำลองกฎของเกมการ์ดอื่น (เช่น Cardfight Vanguard) แม้ Rule Book อ้างเป็นแรงบันดาลใจ ให้ยึดตัวบท Rule Book
- ข้อความการ์ดอาจขัดกับกฎทั่วไปได้เฉพาะส่วนที่ขัด (Rule Book ข้อ 11.1) ระบบความสามารถต้องรองรับหลักนี้
- ภาคผนวก ก ใช้การ์ดสมมติ ห้ามนำไปใช้เป็นข้อมูลการ์ดจริง

## 7. การส่งมอบเอกสาร Rule Book เมื่อมีการแก้กฎ

เมื่อ OWNER แก้ Rule Book ฉบับใหม่ (0.6 เป็นต้นไป) ให้ส่งออกเป็น Markdown ใหม่ วางทับที่ `docs/` ตามชื่อเวอร์ชัน แล้วให้ DEV เทียบความต่างกับฉบับเดิม บันทึกใน `DECISIONS.md` และตรวจว่ามีโค้ดหรือการทดสอบส่วนใดที่ต้องแก้ ก่อนทำงานต่อ
